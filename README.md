# Plus Launcher

Лаунчер Minecraft для Windows на Electron: вход по лицензии Microsoft, **все** версии Mojang,
загрузчики Fabric / Quilt / Forge / NeoForge и встроенный каталог модов из **Modrinth** и **CurseForge**.

## Запуск

```bash
npm install
```

```bash
npm start
```

Сборка установщика (.exe, NSIS):

```bash
npm run build
```

Результат:

- `dist\PlusLauncher-Setup-1.0.0.exe` — установщик (78 МБ): выбор папки, ярлыки на рабочий стол и в меню «Пуск», деинсталлятор. Ставится для текущего пользователя, права администратора не нужны.
- `dist\win-unpacked\Plus Launcher.exe` — уже готовое приложение, запускается без установки.

Ярлык на рабочем столе ведёт на `dist\win-unpacked\Plus Launcher.exe`.

Приложение не подписано сертификатом, поэтому SmartScreen при первом запуске установщика покажет
предупреждение — «Подробнее» → «Выполнить в любом случае».

Если сборка падает на `winCodeSign-2.6.0.7z ... EOF` — GitHub оборвал загрузку инструментов
electron-builder. Их можно скачать вручную в `%LOCALAPPDATA%\electron-builder\Cache\`
(`winCodeSign\winCodeSign-2.6.0`, `nsis\nsis-3.0.4.2`, `nsis\nsis-resources-3.4.1`),
распаковав архивы из релизов `electron-userland/electron-builder-binaries`
(папку `darwin` при распаковке под Windows нужно исключить — там симлинки).

## Что умеет

**Версии**
- Полный манифест Mojang: релизы, снапшоты, old_beta, old_alpha — от `rd-132211` (2009) до последних снапшотов (906 версий на момент сборки).
- Проверка sha1 каждого файла, докачка, параллельная загрузка (12 потоков для библиотек, 24 для ресурсов).
- Распаковка нативных библиотек, поддержка старого (`natives` + classifiers) и нового (1.19+, `:natives-windows`) форматов.
- Legacy-ассеты (`virtual` / `map_to_resources`) для версий до 1.6.

**Загрузчики модов**
- При склейке профиля загрузчика с ванильной версией дубли библиотек убираются по ключу
  `group:artifact[:classifier]`, побеждает версия загрузчика. Иначе на classpath попадают две версии
  ASM (например 9.10.1 из Fabric и 9.6 из самой игры) и загрузчик падает с
  `duplicate ASM classes found on classpath`. Версию загрузчика нельзя подменять на ванильную:
  Forge и NeoForge прописывают её путь в своих аргументах `-p`.
- Fabric и Quilt — через официальные meta-API, ставятся за пару секунд.
- Forge и NeoForge — запуском официального установщика в headless-режиме (`--installClient`).

**Моды**
- Поиск сразу по двум источникам с чередованием результатов, фильтры по версии игры, загрузчику и типу контента (моды, ресурспаки, шейдеры, модпаки, датапаки).
- Установка в один клик в папку конкретной сборки, выбор конкретной версии файла, автоустановка обязательных зависимостей.
- Fabric API / Quilted Fabric API ставится автоматически — CurseForge часто не указывает эту зависимость, и без неё моды падают при старте.
- Перед запуском лаунчер проверяет: если в папке версии есть моды, а Fabric API нет (например, jar закинули руками), он предложит доставить его до старта игры.
- Включение/выключение (`.disabled`) и удаление установленных модов.

**Скины**
- Библиотека скинов лаунчера: `%APPDATA%\.plslauncher\skins`, превью рисуется из самой PNG (голова, тело, руки, ноги + внешний слой), поддержаны 64x64, старый 64x32 и HD.
- Лицензия Microsoft: скин заливается на аккаунт (`POST /minecraft/profile/skins`), выбор Classic/Slim, сброс на стандартный, переключение плащей.
- Оффлайн-профиль: скин кладётся в `<папка версии>\CustomSkinLoader\LocalSkin\skins\<ник>.png`, сам мод CustomSkinLoader ставится кнопкой из Modrinth. Сервера скинов не знают оффлайн-ник, поэтому без мода никак.

**Аккаунты**
- Лицензия Microsoft: device code flow → Xbox Live → XSTS → Minecraft Services, с проверкой покупки игры и автообновлением токена по `refresh_token`.
- Оффлайн-профиль с корректным UUID (`OfflinePlayer:<ник>`, MD5, версия 3).

**Java**
- Автопоиск JDK/JRE в системе (Program Files, JAVA_HOME, PATH, runtime официального лаунчера, ~/.jdks).
- Подбор версии под игру по `javaVersion` из version.json (8 / 16 / 17 / 21).
- Если подходящей нет — скачивание Temurin JRE с api.adoptium.net прямо из лаунчера.

**Сборки (instances)**
- У каждой версии своя папка в корне лаунчера (`1.21.4`) со своими `mods`, `saves`, `config`,
  `resourcepacks`, `shaderpacks` — версии не мешают друг другу.
- Кнопка 📁 на карточке сборки открывает её папку в проводнике.
- Сборки, созданные в старой схеме (`instances\<id>`), переезжают в папку версии автоматически
  при первом запуске — вместе с модами и мирами.

## Где лежат файлы

Папку выбирает пользователь: при первом запуске лаунчер спрашивает, где держать файлы игры,
а позже путь меняется в **Настройки → Папка лаунчера**. Там же видно, сколько уже занято и сколько
свободно на диске. При смене папки можно перенести всё скачанное (внутри одного диска — мгновенно,
на другой — копированием) либо начать с пустой; если в выбранной папке уже лежат данные лаунчера,
он просто подхватит их. После смены лаунчер перезапускается.

Сам путь хранится в `%APPDATA%\PlusLauncher\location.json` — это единственный файл вне выбранной папки.
По умолчанию данные лежат в `%APPDATA%\.plslauncher`. Для отладки путь можно переопределить
переменной окружения `PLUS_LAUNCHER_ROOT`.

У каждой версии — своя папка прямо в корне лаунчера, названная по версии игры,
и внутри неё обычная игровая структура: свои моды, миры, конфиги, скриншоты.

```
<папка лаунчера>\
  config.json      настройки, аккаунты, список сборок
  versions\        version.json + client.jar
  libraries\       библиотеки
  assets\          ресурсы (общие для всех версий)
  natives\         распакованные .dll
  runtime\         скачанные JRE

  1.21.4\          игровая папка версии 1.21.4
    mods\            моды только этой версии
    saves\           миры
    config\          конфиги модов
    resourcepacks\
    shaderpacks\
    logs\, options.txt, screenshots\ — всё пишется сюда

  1.20.1\          то же самое для 1.20.1
  1.20.1-fabric\   если на одну версию заведено несколько сборок
```

Имя папки — это версия игры: сборка на 1.21.4 получает папку `1.21.4`. Если на ту же версию
создать вторую сборку, к имени добавится загрузчик (`1.20.1-fabric`), а дальше номер (`1.20.1-2`),
чтобы моды разных сборок никогда не смешивались.

Общее (версии, библиотеки, ресурсы, Java) лежит в корне и не дублируется — вторая сборка на ту же
версию не качает те же 600 МБ заново.

Каталог `.minecraft` официального лаунчера не трогается.

## Статус в Discord

Лаунчер показывает друзьям в Discord, чем вы заняты:

- в лаунчере — «В лаунчере · Выбрана сборка *название*»;
- в игре — «Играет в Minecraft *версия* · *сборка · загрузчик*» и таймер с момента запуска игры.

Включается в **Настройки → Статус в Discord**. Нужен свой Application ID:

1. Зайти на [discord.com/developers/applications](https://discord.com/developers/applications) → **New Application**,
   назвать её так, как хотите видеть в Discord (это имя будет крупным заголовком статуса).
2. На вкладке **General Information** скопировать **Application ID**.
3. Вставить его в настройках лаунчера. Статус появится сразу — Discord перезапускать не нужно.

Картинка необязательна. Если загрузить изображение на вкладке **Rich Presence → Art Assets**, его имя
вписывается в поле «Ключ картинки» — тогда оно появится в статусе. По умолчанию поле пустое и лаунчер
вообще не шлёт блок `assets`: Discord отвергает активность с несуществующим ключом, и статус пропал бы целиком.

Если лаунчер пишет «Discord на связи», а в профиле пусто — проверьте в самом Discord:
**Настройки → Игровая активность → «Отображать текущую активность как статус»**.

Галочка «Показывать название сборки» убирает название из статуса — останутся только версия и загрузчик.
Если Discord не запущен, лаунчер молча ждёт и подключается сам, когда тот появится.

Внутри — прямой IPC-протокол Discord (`\\?\pipe\discord-ipc-N`, кадр из opcode, длины и JSON),
без сторонних библиотек: `src/main/lib/discord.js`.

## Сайт для скачивания

В папке `docs/` лежит готовая страница: описание, скриншоты, кнопка «Скачать», шаги установки и вопросы.
Она сама подтягивает последний релиз через API GitHub — показывает версию, размер и дату, а кнопка ведёт
прямо на `.exe`. Если релизов ещё нет или репозиторий приватный, кнопка ведёт на страницу релизов.

Адрес сайта после включения Pages: `https://funnyazsupport-ship-it.github.io/Plus-launcher/`

Публикация через GitHub Pages (отдельный хостинг не нужен):

1. Залить проект в репозиторий вместе с папкой `docs/`.
2. **Settings → Pages → Source: Deploy from a branch**, ветка `main`, папка `/docs`, **Save**.
3. Через минуту сайт открывается по адресу `https://<owner>.github.io/<repo>/`.

Репозиторий в `docs/app.js` задаётся строкой `REPO` — тот же, что в `src/main/lib/app-config.js`.
Скриншоты лежат в `docs/img/`, заменяются простой заменой файлов.

**Важно:** и Pages, и скачивание релизов работают только у **публичного** репозитория. У приватного
GitHub не отдаст ни страницу, ни файлы — и проверка обновлений в лаунчере тоже будет молчать.

## Обновления через GitHub

Лаунчер смотрит последний релиз в указанном репозитории и сравнивает его версию со своей.
Репозиторий вписывается в **Настройки → Обновления лаунчера** (`owner/repo` или полная ссылка) —
менять код и пересобирать для этого не нужно. Проверка идёт при запуске (галку можно снять)
и по кнопке «Проверить».

Если вышла новая версия, лаунчер показывает окно с номером версии и описанием релиза. Дальше:

- в релизе лежит `latest.yml` и лаунчер установлен из установщика — кнопка «Скачать и установить»:
  файл качается сам, лаунчер перезапускается и обновляется;
- иначе — кнопка «Открыть страницу релиза», обновление ставится вручную.

### Как выпустить обновление

1. Создать на GitHub **публичный** репозиторий (приватный лаунчер читать не сможет — нужен токен).
2. Один раз вписать `owner`/`repo` в `package.json` → `build.publish` (нужно только для `npm run publish`).
3. Поднять `version` в `package.json`, например на `1.0.1`.
4. Собрать артефакты:

```bash
npm run release
```

5. В `dist` появятся три файла — их и нужно приложить к релизу:
   `PlusLauncher-Setup-1.0.1.exe`, `latest.yml`, `PlusLauncher-Setup-1.0.1.exe.blockmap`.
6. На GitHub: **Releases → New release**, тег `v1.0.1`, приложить эти три файла, опубликовать.

Через несколько секунд лаунчер у пользователей увидит новую версию.

Можно и без ручной загрузки — тогда релиз создастся сам (черновиком):

```bash
npm run publish
```

Для этого нужен токен в переменной окружения `GH_TOKEN` с правом `repo`.

Версия сравнивается по числам (`1.0.10` новее `1.0.9`), предрелизы вида `1.1.0-beta.1`
считаются старше релиза `1.1.0`. Тег может быть и `v1.0.1`, и `1.0.1`.

## Секреты: ключ CurseForge и Discord ID

### Ключ CurseForge

Это настоящий секрет — по нему CurseForge считает запросы на ваш аккаунт. Что сделано:

- **В исходниках его нет.** Вшитый в сборку ключ лежит в `src/main/lib/embedded-key.js`,
  этот файл в `.gitignore` — публикация репозитория ключ не раскроет. Внутри сборки он хранится
  перемешанным, обычный поиск по строкам в `app.asar` его не находит.
- **В `config.json` он зашифрован.** Свой ключ пользователя шифруется через `safeStorage` Electron
  (на Windows это DPAPI): расшифровать можно только под той же учётной записью Windows,
  скопированный на другой компьютер файл бесполезен.
- **В окно настроек ключ не передаётся.** Renderer получает лишь признак «задан свой ключ»;
  сам ключ живёт в main-процессе. Показать его можно кнопкой — тогда он видим 10 секунд.
- Кнопка «Проверить» делает реальный запрос к CurseForge и говорит, принят ключ или нет.

Чего это **не** даёт: программа работает на чужом компьютере, поэтому тот, кто целенаправленно
разберёт сборку, ключ достанет — это верно для любого клиентского приложения. Совсем надёжно только
одно: держать ключ на своём сервере и ходить в CurseForge через него. Если ключ где-то засветился,
отзовите его в консоли CurseForge и выпустите новый — менять код не нужно, новый вписывается в настройках.

### Discord Application ID

**Это не секрет.** Он по своей природе публичен: лаунчер отправляет его в Discord при каждом
подключении, и любой, кто видит ваш статус, может узнать его из профиля приложения. Украсть по нему
нечего — чужой человек в лучшем случае покажет у себя статус с вашим названием.

Секретны у приложения Discord другие вещи — **Client Secret**, **Bot Token** и **Public Key**
со вкладки General Information. Лаунчер их не использует и не хранит, никому не показывайте только их.

В настройках поле с ID по умолчанию скрыто точками — чтобы не светить его на скриншотах и стримах,
рядом кнопка «показать».

## Вход по Microsoft

Используется публичный client id `00000000402b5328` (device code flow), он же меняется в `config.json`
(`msClientId`) — если хотите свой, зарегистрируйте приложение в Azure Portal с разрешением
`XboxLive.signin` и включённым публичным клиентом.

Для входа нужен аккаунт с купленной Minecraft: Java Edition — иначе лаунчер честно скажет об этом
(проверка через `entitlements/mcstore`).

## Оформление

Плоский тёмный интерфейс без градиентов, свечения и эмодзи: острые углы (3 px), одна акцентная
зелёная краска, тонкие рамки, моноширинный шрифт для всего технического — версий, путей, счётчиков.
Иконки — собственный SVG-набор в `index.html` (`<symbol id="i-...">`), логотип и иконка приложения —
изометрический блок, он же рисуется в `build/icon.png` скриптом на Electron.

## Установка и удаление

- Установщик сам сносит предыдущую версию перед распаковкой новой — файлы разных версий не смешиваются.
  Этим занимается electron-builder: он запускает старый деинсталлятор молча, сохраняя файлы игры.
- При удалении лаунчера появляется страница с галочкой **«Удалить также версии, моды и миры»**.
  Без галочки папка с игрой остаётся на диске и подхватится при следующей установке.
  Путь к ней деинсталлятор берёт из реестра (`HKCU\Software\Plus Launcher\DataDir`) — лаунчер пишет
  его при каждом запуске, поэтому работает и с папкой на другом диске.
- Во время обновления деинсталлятор запускается молча, страница не показывается и файлы игры не трогаются.

Код страницы — `build/installer.nsh`. Уминаться в NSIS помогают два правила: файл подключается раньше
библиотек, поэтому `LogicLib.nsh` и `nsDialogs.nsh` подключаются в нём самом, а весь код деинсталлятора
должен лежать внутри `!ifdef BUILD_UNINSTALLER` — иначе makensis ругается на неиспользуемые переменные.

## Скорость запуска

Перед стартом игры лаунчер сверяет файлы. Полная сверка версии с модами — это около сотни библиотек
и несколько тысяч ресурсов, и подсчёт sha1 для каждого занимал секунды на каждый запуск.

- После полной установки в папке версии появляется отметка `.installed`.
- При следующих запусках идёт быстрая сверка: размеры библиотек и клиента плюс выборка из ~60 ресурсов.
  Если что-то не сходится — автоматически включается полная установка и недостающее докачивается.
- Ресурсы игры при проверке сверяются по размеру, а не по sha1: их имена и так являются хешами,
  а свежескачанное всё равно проверяется полностью.

На практике проверка перед запуском сократилась с ~4,5 с до 0,1 с.

## Тонкости, на которых легко споткнуться

- Игра запускает **два** java-процесса, и второй наследует stdout/stderr. Поэтому лаунчер слушает
  событие `exit` дочернего процесса, а не `close` (`close` не наступит, пока жив внук), а кнопка
  «Остановить» снимает всё дерево процессов через `taskkill /T /F` — иначе игра остаётся в памяти.
- Библиотеки после склейки с профилем загрузчика дедуплицируются, победитель — версия загрузчика.
- В 1.19+ jar-ы с нативами остаются в classpath и одновременно распаковываются.
- `${version_name}` подставляется как базовая версия игры — от этого зависит `-DignoreList` у Forge.
